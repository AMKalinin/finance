# Сводка по индексам базы данных Finance Backend

## Обзор

Добавлены индексы для оптимизации частых запросов к базе данных. Индексация улучшает производительность при фильтрации, сортировке и JOIN операциях.

---

## Добавленные индексы

### 1. **Account (Счета)**
| Имя индекса | Поля | Назначение |
|-------------|------|------------|
| `ix_account_user_is_deleted` | `(user_id, is_deleted)` | Быстрый поиск активных счетов пользователя |
| `ix_account_user_archived` | `(user_id, is_archived)` | Поиск архивированных счетов |
| `ix_account_user_primary` | `(user_id, is_primary)` | Поиск основных счетов |
| `ix_account_type` | `account_type` | Фильтрация по типу счета |

**Поля с одиночными индексами:**
- `user_id` - внешний ключ на пользователя

---

### 2. **Category (Категории)**
| Имя индекса | Поля | Назначение |
|-------------|------|------------|
| `ix_category_user_type` | `(user_id, type)` | Поиск категорий по пользователю и типу |
| `ix_category_parent_level` | `(parent_id, level)` | Иерархические запросы (дерево) |
| `ix_category_user_is_deleted` | `(user_id, is_deleted)` | Активные категории пользователя |

**Поля с одиночными индексами:**
- `type` - внешний ключ на тип категории
- `parent_id` - рекурсивная связь (родительская категория)
- `user_id` - внешний ключ на пользователя

---

### 3. **Transaction (Транзакции)**
| Имя индекса | Поля | Назначение |
|-------------|------|------------|
| `ix_transaction_user_date` | `(date)` | Поиск транзакций по дате |
| `ix_transaction_account_type` | `(from_account_id, to_account_id, type)` | Сложные запросы с фильтрацией по счетам и типу |
| `ix_transaction_category_status` | `(category, status)` | Фильтрация по категории и статусу

**Поля с одиночными индексами:**
- `from_account_id` - внешний ключ на источник средств
- `to_account_id` - внешний ключ на получателя
- `category` - внешний ключ на категорию
- `type` - тип транзакции (debit, adding, transfer)

---

### 4. **Transaction_distribution_user (Распределения)**
| Имя индекса | Поля | Назначение |
|-------------|------|------------|
| `ix_transaction_dist_user_status` | `(user_id, is_deleted)` | Поиск распределений пользователя |
| `ix_transaction_dist_role_status` | `(distribution_user_role, distribution_status)` | Фильтрация по роли и статусу

**Поля с одиночными индексами:**
- `transaction_id` - внешний ключ на транзакцию (в составе PK)
- `user_id` - внешний ключ на пользователя (в составе PK)

---

### 5. **Friends (Друзья)**
| Имя индекса | Поля | Назначение |
|-------------|------|------------|
| `ix_friends_user1_status` | `(user1_id, status)` | Поиск запросов от пользователя |
| `ix_friends_user2_status` | `(user2_id, status)` | Поиск запросов пользователю

**Поля с одиночными индексами:**
- `user1_id`, `user2_id` - составной первичный ключ

---

### 6. **Position (Позиции)**
| Имя индекса | Поля | Назначение |
|-------------|------|------------|
| `ix_position_transaction` | `(transaction_id)` | Поиск позиций по транзакции

**Поля с одиночными индексами:**
- `transaction_id` - внешний ключ на транзакцию

---

### 7. **Position_user (Доли в позициях)**
| Имя индекса | Поля | Назначение |
|-------------|------|------------|
| `ix_position_user_position` | `(position_id)` | Поиск долей по позиции |
| `ix_position_user_user` | `(user_id)` | Поиск позиций пользователя

**Поля с одиночными индексами:**
- `position_id`, `user_id` - составной первичный ключ

---

### 8. **User (Пользователи)**
| Имя индекса | Поля | Назначение |
|-------------|------|------------|
| `ix_user_subscription_type` | `(subscription_type)` | Поиск пользователей по типу подписки

**Поля с одиночными инексами:**
- `subscription_type` - внешний ключ на тип подписки
- `subscription_expiry` - дата истечения подписки

---

## Рекомендации по обслуживанию

### 1. **Пересоздание таблиц**
После добавления новых моделей или изменений в схемах:
```bash
# Удалить старую БД (для разработки)
rm finance_db.sqlite test_finance_db.sqlite

# Пересоздать таблицы с индексами
python -c "from app.db.session import engine; from app.db.base_class import Base; Base.metadata.create_all(bind=engine)"
```

### 2. **Мониторинг производительности**
Проверьте эффективность запросов:
```sql
-- PostgreSQL (если переключитесь на него)
EXPLAIN ANALYZE SELECT * FROM account WHERE user_id = '...' AND is_deleted = false;

-- SQLite
EXPLAIN QUERY PLAN SELECT * FROM account WHERE user_id = '...' AND is_deleted = false;
```

### 3. **Удаление неиспользуемых индексов**
Индексы замедляют INSERT/UPDATE, поэтому удаляйте их если:
- Нет запросов с фильтрацией по этим полям
- Таблица маленькая (< 10k записей)

---

## Ограничения SQLite

При использовании SQLite (по умолчанию):
- **Ограничение**: До ~256 индексов на таблицу
- **Рекомендация**: Для продакшена используйте PostgreSQL с более мощной системой индексации
