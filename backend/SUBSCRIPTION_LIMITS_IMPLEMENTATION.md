# Реализация ограничений для бесплатных пользователей

## Обзор изменений

Добавлена логика для ограничения функционала бесплатных пользователей (subscription_type = 'free').

## Ограничения для бесплатной подписки

### 1. Лимит на количество счетов (accounts)
- **Бесплатные пользователи**: максимум 1 активный счет
- **Платные пользователи**: без ограничений

**Метод проверки**: `Fin_app.check_account_limit()`

### 2. Лимит на категории (categories)
- **Бесплатные пользователи**: 
  - Максимум 5 категорий уровня 1 (без вложенности)
  - Запрещено создание вложенных категорий
- **Платные пользователи**: 
  - Максимум 10 категорий
  - Можно создавать вложенность до уровня 3

**Метод проверки**: `Fin_app.check_category_limit()`

### 3. Лимит на транзакции (transactions)
- **Бесплатные пользователи**: максимум 5 транзакций в день
- **Платные пользователи**: без ограничений

**Метод проверки**: `Fin_app.check_transaction_daily_limit()`

## Реализация

### Новые исключения

Добавлены три новых класса исключений в `app/err/errors.py`:

1. **AccountLimitError** - ошибка превышения лимита счетов
   - HTTP код: 402 (Payment Required)
   - Код ошибки: ACCOUNT_LIMIT_ERROR

2. **CategoryLimitError** - ошибка превышения лимита категорий
   - HTTP код: 402 (Payment Required)
   - Код ошибки: CATEGORY_LIMIT_ERROR

3. **TransactionDailyLimitError** - ошибка дневного лимита транзакций
   - HTTP код: 402 (Payment Required)
   - Код ошибки: TRANSACTION_DAILY_LIMIT_ERROR

### Модифицированные методы Fin_app

1. **create_account()**: добавлен вызов `check_account_limit()` перед созданием счета

2. **create_category()**: 
   - Добавлен вызов `check_category_limit()` перед проверкой родительской категории
   - Для бесплатных пользователей проверяется попытка создания вложенной категории

3. **create_transaction()**: добавлен вызов `check_transaction_daily_limit()` перед созданием транзакции

### Новые методы проверки лимитов

1. **check_account_limit()** (commit)
   - Проверяет количество активных счетов пользователя
   - Для бесплатных пользователей: если >= 1, raises AccountLimitError

2. **check_category_limit()** (commit)
   - Для бесплатных пользователей: считает категории уровня 1
   - Если >= 5, raises CategoryLimitError
   - Дополнительно проверяет попытку вложенной категории

3. **check_transaction_daily_limit()** (commit)
   - Считает транзакции за текущий день
   - Использует JOIN с transaction_distribution_user для получения транзакций пользователя
   - Если >= 5, raises TransactionDailyLimitError

## Тестирование

### Сценарии для тестирования

1. **Бесплатный пользователь создает первый счет** - ✅ Успех
2. **Бесплатный пользователь пытается создать второй счет** - ❌ AccountLimitError
3. **Платный пользователь создает счета без ограничений** - ✅ Успех
4. **Бесплатный пользователь создает 5 категорий уровня 1** - ✅ Успех
5. **Бесплатный пользователь пытается создать 6-ю категорию уровня 1** - ❌ CategoryLimitError
6. **Бесплатный пользователь пытается создать вложенную категорию** - ❌ CategoryLimitError
7. **Платный пользователь создает категории с вложением** - ✅ Успех (до уровня 3)
8. **Бесплатный пользователь создает 5 транзакций в день** - ✅ Успех
9. **Бесплатный пользователь пытается создать 6-ю транзакцию в тот же день** - ❌ TransactionDailyLimitError
10. **На следующий день бесплатному пользователю доступны новые транзакции** - ✅ Успех

## Примечания

1. Все проверки лимитов выполняются с декоратором `@commit`, что гарантирует атомарность операций
2. Лимиты проверяются только для пользователей с `subscription_type = 'free'`
3. При проверке транзакций учитываются только не-удаленные распределения (`is_deleted=False`)
4. Для категорий учитываются только активные категории (`is_deleted=False`)
5. HTTP код 402 (Payment Required) используется для сигнализации о необходимости подписки
